# 实现 Stope 虚拟机

> **这是一份指南，不是规范。**
>
> Stope 只规定三件事：**Stope 语言**、**STML**、**Stope 编译器**（AST → `Program` 的产物格式）。
> **它不规定虚拟机。** 拿到一份 `Program` 之后怎么让它跑起来，完全由你决定 ——
> 栈式字节码解释、寄存器机、直接遍历 AST、转译成 C / LLVM IR / 宿主语言的闭包，都合规。
>
> 本文讲解「如果要自己写一个执行器，该怎么做」。文里的具体做法来自 C++ 参考实现
> （`cpp/include/stope/basic_vm.hpp`），它是**一种可行解**，不是必须照抄的标准答案。

## 1. 起点：拿到 Program 之后

`Program` 的字段与编码是标准，见 [compiler-test-plan.md](compiler-test-plan.md) §2。
这里只列**执行器最关心的几点**：

| 字段 | 执行器怎么用 |
| --- | --- |
| `opcodes` | 指令与操作数**混排**在一个序列里；元素是 16 位整数 |
| `variableNum` | 变量槽位总数。执行前把槽位容器开到这个长度，**含已回收、不再使用的槽位** |
| `exports` | 名字 → 槽位。**宿主只看得见这些**（`let` 声明的局部变量不在里面） |
| `intConsts` / `floatConsts` / `stringConsts` / `binArrConsts` | 四个常量池；`PushXxx` 的操作数是**池子下标** |
| `maxReturnNum` | 所有 `return` 里最大的返回值个数，可用来预分配返回值缓冲 |
| `requiredStackSize` | 执行期栈深度的**峰值**，可用来预分配栈 |

两个容易忽略的点：

- `stringConsts` 是 **UTF-16**（`std::u16string`）。如果你的宿主语言用 UTF-8，取值时要转码。
- `requiredStackSize` 是编译器**线性记账**估出来的（遇到分支要手动「掰回去」，见
  `cpp/include/stope/compiler.hpp` 的 `StackSizeManager::converge`）。它是上界估计，
  拿它预分配没问题，但别拿它当断言。

## 3. 值系统

Stope 是动态类型语言，每个值应当存储有一个类型标记。也可以借助宿主的动态类型来省去类型标记，例如 JavaScript、Python 等语言本身就是动态类型，或利用 C# 的 object、go 的 any 等。

至少要能表示这 6 种值：
- null
- 整数
- 浮点数
- 字节数组
- 字符串
- 标识符索引
Stope 有 PushFalse、PushTrue 向栈压入布尔值，可以借助整数实现。

### 布尔值的一个岔路口

参考实现**没有独立的 Bool 类型**：`true` / `false` 编译成 `PushTrue` / `PushFalse`，
参考实现压的就是整数 `1` / `0`。

这带来一个可观察的后果：

```stope
true == 1;   // 参考实现：真。因为 true 就是整数 1
```

[syntax-reference.md](syntax-reference.md) §4.4 只说 `==` 等比较「不做布尔折算，由运行期判断」，
**没有规定 `true == 1` 必须是真还是假**。所以：

- 不建独立 Bool 类型（照参考实现）→ `true == 1` 为真，实现简单，与常量折叠好对齐；
- 建独立 Bool 类型 → `true == 1` 为假，语义更"干净"，但你在折叠、算术折算、
  比较运算里都要额外处理 Bool，且要与常量折叠的结果保持一致。

无论选哪个，**必须保证常量折叠与运行期的结果一致**（见 §8 的表格与 §12）。

## 4. 栈、变量槽与「左值」

### 4.1 变量槽位

- 容器长度 = `program.variableNum`，下标即槽位号。
- 槽位号来自编译期分配：`export` 出来的名字在 `exports` 里能查到；`let` 声明的查不到。
- 未初始化的槽位填 `Null`。

### 4.2 `PushId` 压的是**变量本身**，`PushValue` 压的是**值**

这是设计上最关键的一点，也是 2026-10-22 拆分两条指令的原因。

因为 `Assign` 不携带操作数 —— 它从栈上取「写到哪里」：

```stope
x = 1;
```

编译成 `PushId(槽位) PushInt(常量1) Assign`。如果压的是值，`Assign` 就无从知道目标
是哪个槽位。所以**当赋值目标**时，压进栈的必须是一个「引用」而不是值。

但读变量值的时候恰恰相反 —— 你要是也压引用，执行器就得在每条读值路径上自己解一次引用。
拆成两条指令，这个判断就挪到了编译期（编译器明确知道自己在左值还是右值位置）：

| 指令 | 压什么 | 谁生成 |
| --- | --- | --- |
| `PushId` | 变量槽位**本身**（引用 / 左值） | 有赋值的 `let` 左侧；赋值语句等号左侧恰好是裸标识符时 |
| `PushValue` | 槽位**当前的值**（压栈时就取出来） | 其余一切读变量的位置：表达式、被调用者、被索引的容器、条件、`return` 的值… |

判据在 `compiler.cpp` 的 `onVisitAssignStmt`：只有 `leftExpr` 是 `IdentExpr` 才 emit
`PushId`，否则 `Visit(leftExpr)` 走普通读值。所以 `a[0] = 1;` 里的 `a` 是 `PushValue`。

```cpp
// 编译器里两处 emit 的原话（cpp/src/compiler.cpp）
emitOp(Opcode::PushId);     // 压的是变量本身，不是值，否则无法赋值
emitOp(Opcode::PushValue);  // onVisitIdentExpr：读变量，压它的值
```

## 5. 指令语义（33 条 + 自定义）

编号由标准钉死（见 [compiler-test-plan.md](compiler-test-plan.md) §2.1）。
下表写的是**执行器需要实现的语义**；栈效果用 `[…] → […]` 表示，右边是栈顶。

### 5.1 变量与常量

| 指令 | 操作数 | 栈效果 | 语义 |
| --- | --- | --- | --- |
| `PushId` | 槽位号 | `[] → [ref]` | 压入变量的**引用**（左值），见 §4.2 |
| `PushValue` | 槽位号 | `[] → [v]` | 压入变量的**值**（右值），见 §4.2 |
| `PushNull` | — | `[] → [v]` | 压 `Null` |
| `PushFalse` / `PushTrue` | — | `[] → [v]` | 压假 / 真（参考实现压整数 `0` / `1`） |
| `PushInt` | `intConsts` 下标 | `[] → [v]` | 压整数常量 |
| `PushFloat` | `floatConsts` 下标 | `[] → [v]` | 压浮点常量 |
| `PushString` | `stringConsts` 下标 | `[] → [v]` | 压字符串常量（UTF-16） |
| `PushBinArr` | `binArrConsts` 下标 | `[] → [v]` | 压二进制数组常量 |
| `Assign` | — | `[ref, v] → []` | 把 `v` 存入 `ref` 指向的槽位，**弹两个** |

Stope 的赋值语句允许等号左侧是表达式，而不仅仅是标识符。因此可以在等号左侧放置通过 VM 实现的变量索引，例如数组中变量的索引。
```
a = Array:NewSized(10); // 创建一个长度为 10 的空数组
a[0] = 1;
```

### 5.2 调用与索引

| 指令 | 操作数 | 栈效果 | 语义 |
| --- | --- | --- | --- |
| `Call` | 实参个数 `n`（**不含 callee**） | `[callee, a₁…aₙ] → [ret]` | 调用。参数从左到右入栈，栈顶是最后一个 |
| `At` | 下标个数 `n` | `[container, k₁…kₙ] → [v]` | 按下标取元素 |

- `Call` 的 callee 入栈后在参数**下面**。取值时它必须解析成 `HostFunction`，否则报错。
- `At` 目前**只规定了 `n == 1` 的行为**：下标必须是整数，越界报错；容器可以是 `String`
  （返回一个 UTF-16 码元，作为整数）或 `BinArr`（返回一个字节）。
  多下标（`a[1, 2]`）参考实现直接报「未实现」，你打算支持的话要自己定语义。

### 5.3 运算

| 指令 | 操作数 | 栈效果 | 语义 |
| --- | --- | --- | --- |
| `Pop` | — | `[v] → []` | 丢弃栈顶（表达式语句的结果） |
| `Minus` | — | `[v] → [v]` | 一元负号，只对数值 |
| `Not` | — | `[v] → [v]` | 逻辑非，结果压整数 `0` / `1`；`not null` 为真 |
| `Pow` `Mul` `Div` `IDiv` `Mod` `Add` `Sub` | — | `[l, r] → [v]` | 二元运算，`l` 在下、`r` 在上 |
| `EQ` `NE` `LT` `LE` `GT` `GE` | — | `[l, r] → [v]` | 比较，结果压整数 `0` / `1` |

具体的类型组合行为见 §8（那是标准）。

### 5.4 控制流与返回值

| 指令 | 操作数 | 栈效果 | 语义 |
| --- | --- | --- | --- |
| `If` | 跳转目标 | `[cond] → []` | **弹出条件**；条件为**假**时跳到目标 |
| `GoTo` | 跳转目标 | 不变 | 无条件跳转 |
| `GetArg` | — | `[k] → [v]` | 取第 `k` 个入参，替换栈顶 |
| `ArgNum` | — | `[] → [v]` | 压入参个数（`argc`） |
| `Return` | 返回值个数 `n` | 不变 | 取栈顶 `n` 个作为返回值，**终止程序** |

### 5.5 自定义指令

- 指令值 **> `Return`（31）** 的都是自定义指令，由宿主在**编译前**注册
  （见 [syntax-reference.md](syntax-reference.md) §5.3）。
- 栈效果 `[a₁…aₙ] → [ret]`：**没有 callee 入栈**，这一点与 `Call` 不同。
- 变长参数指令的编译结果**多带一个操作数**（实参个数）；定长的不带。
- 语义完全由宿主定义 —— 你的执行器要能在分派表里认出这些编号并转给宿主。

## 6. 控制流：If / GoTo

### 6.1 操作数是 opcodes 的下标

跳转目标 = `opcodes` 的**槽位索引**，不是字节偏移。目标可能**等于 `opcodes.size()`**
（跳到程序末尾），执行器必须把它当作「结束」，不能越界读。

### 6.2 `If` 跳的是「条件为假」那一支

这是最容易搞反的一点：`If` 的操作数是**条件为假时**要去的地方，条件为真就顺序执行下去。

```stope
export x; if x < 3 { x = 1; } else { x = 2; }
```

实测反汇编（`DumpProgramNoCustom` 输出，已删去常量池部分）：

```
[0]     PushValue  0        // x 是读值 → PushValue
[2]     PushInt    0        // intConsts[0] == 3
[4]     LT
[5]     If         14       // 条件为假 → 跳到 14（else 分支）
[7]     PushId     0        // x 是赋值目标 → PushId
[9]     PushInt    1        // intConsts[1] == 1
[11]    Assign
[12]    GoTo       19       // 分支走完，跳出整个 if（19 == 程序末尾）
[14]    PushId     0
[16]    PushInt    2
[18]    Assign
```

`while` 循环同理，末尾一条 `GoTo` 回到条件处：

```stope
let i = 0; while i < 3 { i = i + 1; } return i;
```

```
[0]     PushId     0        // let i = 0 的目标
[2]     PushInt    0
[4]     Assign
[5]     PushValue  0        // 条件里的 i 是读值
[7]     PushInt    1
[9]     LT
[10]    If         22       // 假 → 跳到 22（循环之后）
[12]    PushId     0        // i 是赋值目标
[14]    PushValue  0        // 右侧的 i 是读值
[16]    PushInt    2
[18]    Add
[19]    Assign
[20]    GoTo       5        // 回到条件
[22]    PushValue  0        // return i
[24]    Return     1
```

### 6.3 记账方式由你决定

参考实现的 `Run()` 是这样的：

```cpp
while (i < program->opcodes.size()) {
  api->opFuncs[program->opcodes[i]](*api, *this);
  if (HasError()) return Result::Error;
  ++i;                                   // ← 循环末尾统一推进
}
```

所以它的 `opIf` 里写的是 `s.i = goToIdx - 1`（先减 1，让末尾的 `++i` 补回来），
`opGoTo` 读的是 `opcodes[s.i + 1]`（操作数在指令自己后面）。

**这是它自己的记账方式，不是格式的一部分。** 如果你的循环是自己推进指令指针的，
直接 `i = target` 即可，不要照抄那个 `- 1`。

## 7. 宿主接口

接口长什么样不由标准规定，但**这四件事每个执行器都要解决**。

### 7.1 `exports` 的两类用途

`exports` 里的名字是**宿主唯一能看见的变量**。宿主拿它做两件事：

1. **放接口** —— 把宿主函数写进槽位，脚本就能调用：

   ```cpp
   auto& slot = state.variables[program.exports[u"fmt:println"]];
   slot.type = Value::Type::HostFunction;
   slot.data.hostFuncPtr = hostPrintln;
   ```

2. **当程序参数** —— 执行前预置变量，脚本直接读：

   ```cpp
   state.variables[program.exports[u"threshold"]] = /* ... */;
   ```

`let` 声明的局部变量**不会**出现在 `exports` 里，宿主看不到名字，只有槽位号。

### 7.2 遍历 exports 时的陷阱

**未声明就使用的名字也会被登记进 `exports`**（编译器把它当作外部变量）。
实测：

```stope
fmt:println(1);   // 名字没声明过
```

编译后 `exports = { "fmt:println" → 0 }`。这是特性（宿主据此知道自己需要提供什么），
但意味着：

> 遍历 `exports` 时**不要用会插入元素的下标运算**（C++ 的 `std::map::operator[]`、
> Python 的 `defaultdict` 之类）。查一个不存在的名字会把它插进去并返回槽位 0，
> 于是宿主函数被静默绑到变量 0。用 `find` / `at` / `get`。

### 7.3 宿主函数

参考实现的宿主函数就是一个**值**（`HostFunction`），放在槽位里，`Call` 时检查类型。
签形大致是：

```cpp
void (*)(State& state, std::span<const Value> args, Value& output);
```

- `args` 是栈上那 `n` 个实参的视图，**顺序与源码一致**。
- 写 `output` 即返回值；`Call` 之后栈顶就是它（栈效果 `[callee, a…] → [ret]`）。
- 出错时往 `state.errors` 里写一条。

> 函数指针**没有 udata 通道**，所以只有不捕获的 lambda 能转换过去。
> 需要上下文就用全局变量，或者改你的接口（这是你的自由，标准不管）。

### 7.4 入参：Arguments

`args[expr]` → `GetArg`，`argc` → `ArgNum`。执行器需要一个「按索引取值」的对象，
参考实现是：

```cpp
struct Arguments {
  virtual Result at(State& state, const Value& indexOrKey, Value& out) = 0;
  virtual std::int64_t num() = 0;
};
```

没有设置入参时执行 `args[0]` / `argc` 应该报错（参考实现：`no args.`），不要读空指针。

## 8. 必须实现的语言语义

**这一节是标准**，来自 [syntax-reference.md](syntax-reference.md) §4.4 与 §2。
不管你选哪条执行路线，行为都得对上。

### 8.1 三条项目自定规则

| 规则 | 例子 | 结果 |
| --- | --- | --- |
| 二进制数组相加 = 字节连接 | `'x 41' + 'x 42'` | 两字节 `41 42` |
| 字符串 / 数组 × 非负整数 = 重复（左右都行） | `"ab" * 3`、`3 * "ab"` | `"ababab"` |
| 算术里 `true` / `false` 当作 `1` / `0` | `true + 1` | `2` |

### 8.1.1 算术细则（2026-10-21 统一，折叠与运行期必须一致）

| 情况 | 规则 |
| --- | --- |
| 整数 `/` | **除不尽 → 浮点数**：`7 / 2` 是 `Float(3.5)`，`6 / 2` 是 `Int(3)`。整除用 `idiv` |
| `idiv` | 向零取整（`-7 idiv 2` 是 `-3`）；任一侧是浮点则结果仍是浮点（`7 idiv 2.0` 是 `Float(3)`） |
| `%` | 余数符号跟被除数（C 语义）：`-7 % 3` 是 `-1` |
| `^` | 两个整数且指数 ≥ 0 → 整数；**负指数 → 浮点数**：`2 ^ -1` 是 `Float(0.5)` |
| `null` | **不能参与算术**：`+ - * / idiv % ^` 遇到 null 一律报错（不是 0，也不是单位元）。`null == null` 仍为真 |
| 整数溢出 | **不检查**，按 64 位补码回绕：`INT64_MAX + 1` → `INT64_MIN` |
| 整数除零 | 只有**两侧都是整数**才拦：`1 / 0`、`1 % 0`、`1 idiv 0` → **报错**（不要让它走到硬件除法，那会崩进程） |
| 浮点除零 | 任一侧是浮点就走 IEEE，**不拦**：`1.0 / 0.0`、`1 / 0.0`、`1.0 / 0` 都是 `inf`；`0.0 / 0.0` 是 `nan`。别只判「除数是整数 0」——那会让 `1.0 / 0` 报错而同值的 `1 / 0.0` 得 `inf` |

> 参考实现 `cpp/include/stope/basic_vm.hpp` 已按上表实现；错误文本形如
> `"Div" division by zero. ` / `"Add" cannot operate on null. `。

### 8.2 真值

| 值 | 真假 |
| --- | --- |
| `Null` | 假 |
| 整数 / 浮点 | 非零为真 |
| 字符串 / 二进制数组 | **非空为真** |
| `HostFunction` | 非空指针为真 |

实测：`if "" {…}` 不进分支，`if "a" {…}` 进分支。

### 8.3 参考实现实测值（都是跑出来的）

用变量写、绕过常量折叠的运行期结果：

| 表达式 | 结果 |
| --- | --- |
| `a / b`（`7`、`2` 两个整数） | `Float(3.5)`（除不尽 → 浮点） |
| `7 / 2`（字面量，走**折叠**） | `Float(3.5)` —— 与上一条一致 |
| `a / b`（`6`、`2`） | `Int(3)`（除得尽仍是整数） |
| `a idiv b` | `Int(3)` |
| `a % b`（`7`、`2`） | `Int(1)`；`a` 为 `7.5` 时 `Float(1.5)` |
| `s * n`（`"ab"`、`2`） | `"abab"` |
| `s + i`（`"ab"`、`1`） | 报错 |
| `b + 1`（`true`） | `Int(2)` |
| `null + 1` | 报错 `"Add" cannot operate on null. ` |
| `a / z`（`1`、`0`） | 报错 `"Div" division by zero. ` |
| `a / z`（`1.0`、`0.0`） | `inf`（浮点除零不报错） |
| `s * n`（整数在左：`2`、`"ab"`） | `"ababab"` —— 与 `"ab" * 2` 同 |
| `a idiv b`（`7`、`-2`） | `Int(-3)`（向零取整） |
| `p + q`（`'x 41'`、`'x 42'`） | 两字节 `41 42` |
| `1 < 2.0` | `Int(1)`（跨类型比较按数值） |
| `null == null` | 真；`null == 1` 假 |
| `true == 1` | 真（因为参考实现里 `true` 就是整数 `1`，见 §3） |
| `not null` | `Int(1)` |

---

## 9. 错误处理与终止

参考实现的约定（你可以改）：

- 出错**立即停**，错误文本形如 `"14: 'Assign' can only assign to a variable. "`，
  前缀是指令下标。
- 返回值用 `Result` 枚举（`Success` / `Error` / `UnknownError` /
  `DuplicateWithBuiltinOpcode`）。
- 返回值通过 `Return` 收集：栈上 `n` 个值构成一个视图。**源码没有 `return` 时
  返回列表是空的**，执行器不能假设至少有一个。

运行期需要检查的情形：

| 情形 | 建议 |
| --- | --- |
| 栈下溢 | 报错，不要读空栈 |
| 类型不匹配（`Add` 遇到不支持的组合等） | 报错并指出指令位置 |
| 下标越界（`At`、`args[i]`） | 报错 |
| **整数除零**（`/` `%` `idiv`） | 参考实现已显式检查并报错（`"Div" division by zero. `）。**别把 `a / b` 直接写成 C 的 `/`** —— 不检查就触发硬件异常，整个进程没了 |
| 调用非函数 | 报错 |

## 10. 实施步骤

1. **先做 dump，别先写 VM。** 用 `cpp/include/stope/debug.hpp` 的
   `DumpProgramNoCustom(program)`（或自己写一份），确认你能看懂真实产物的指令流。
   §6.2 的两段反汇编就是这么来的。
2. **值 + 栈 + 变量槽。** 只做 `Null` / 整数 / 浮点，先不管字符串与数组。
3. **无跳转的指令。** `PushXxx`、`Assign`、算术、比较、一元运算。
   用 `let a = 1; let b = 2; return a + b;` 验收。
4. **控制流。** `If` / `GoTo`。用例要覆盖 `if / elif / else`、`while`、
   可省略条件的 `while { }`、`break` / `continue`。
5. **调用与返回值。** `Call` / `Return`，加一个宿主函数（`fmt:println` 之类）验证。
6. **入参。** `GetArg` / `ArgNum`。
7. **字符串与二进制数组。** 这时才需要认真设计内存管理（句柄 + 引用计数 / GC / 拷贝）。
8. **自定义指令。** 分派表里留出 > 31 的编号。
9. **性能。** 分派改成表驱动或 `switch`、常量池预装载、栈预分配到 `requiredStackSize`。

## 11. 验收：与参考实现对拍

两套办法，建议一起用：

**① 对拍产物。** 用 [compiler-test-plan.md](compiler-test-plan.md) §2.3 的序列化格式
把 `Program` 打成一行字符串，和参考实现的输出逐字比对。这能区分「编译器错」还是
「执行器错」。

**② 对拍行为。** 准备一批 Stope 源码，两边各跑一遍，比对返回值与错误。建议至少覆盖：

- 三种循环与分支，含条件省略、`break` / `continue`、嵌套
- 六种值类型各自的运算，尤其是字符串连接、数组连接、重复
- 多返回值 `return 1, 2;`
- 没有 `return` 的程序（返回列表为空）
- 宿主函数、入参、`argc`
- 自定义指令（定长 / 变长 / 零参数）
- 每一类运行期错误（下溢、类型不匹配、越界、除零、调用非函数）

**写用例时注意常量折叠**：两侧都是字面量的表达式会在**解析期**就算掉，根本到不了运行期。
要测运行期行为，就把操作数放进 `let` 变量里（§8.3 的表格就是这么做的）。

## 12. 已知坑

按踩到的概率排序。

1. **`If` 的跳转方向搞反** —— 它跳的是「条件为假」那一支，不是为真。
2. **`If` 忘记弹条件** —— 条件留在栈上会让后续每个值整体错位一层，
   症状是 `Assign` 报 "can only assign to a variable"（它从 `AtTop(2)` 取到的是陈旧值）。
3. **`GoTo` 读错操作数** —— 操作数在指令自己后面；到底读 `i` 还是 `i+1`
   取决于你的指令指针在哪一步推进（§6.3）。
4. **循环变量用了指令指针** —— 参考实现里 `State::i` 是指针，
   早期某个辅助函数把 `State::i` 当循环变量用，直接死循环。
5. **栈顶「从 0 起算」还是「从 1 起算」不统一** —— 参考实现统一用「从栈顶数、1 起算」
   （`AtTop(1) == stack.back()`）。混用会差一格。
6. **跳转目标等于 `opcodes.size()`** —— 是合法的「结束」，要单独处理。
7. **宿主函数没有 udata 通道** —— 捕获 lambda 转不成函数指针（§7.3）。
8. **遍历 `exports` 用会插入元素的下标运算** —— 会把不存在的名字静默绑到槽位 0（§7.2）。
9. **整数除零** —— 不检查就直接除，硬件异常会终止进程（不是抛异常，是没了）。
   `/` `%` `idiv` 三处都要先判断除数（§8.1.1、§9）。
10. **常量折叠与运行期不一致** —— 这类分歧最难查：同一个表达式写成字面量和写成变量
    结果不同。2026-10-21 起参考实现的折叠与运行期已经完全对齐（`/` 除不尽得浮点、
    `^` 负指数得浮点、null 不参与算术、整数溢出回绕、除零报错，
    逐条见 §8.1.1）。**自己实现时也要两边一起改**，改动后跑一遍「字面量 / 变量」对拍。
11. **字符串乘法的两侧** —— `s * n` 与 `n * s` 都要测。参考实现早期版本只处理了
    序列在左的情况，整数在左时会拿整数的 union 当句柄用（垃圾下标），直接崩溃；
    现在两侧都走同一个 `seq` 分支。
12. **`7 idiv 2.0` 写错 union 成员** —— 类型标成 `Float` 却写 `data.integer`，
    读出来是垃圾。类型与 union 成员必须配套。
